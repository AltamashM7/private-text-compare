# Durable decisions

- **D001 — Static-first Astro architecture.** Production output is static unless a later approved requirement changes this.
- **D002 — Preact only for necessary interactive islands.** Do not hydrate components merely to demonstrate framework presence.
- **D003 — Framework-independent application logic lives under `src/core/`.** Core logic must not depend on Astro or Preact components.
- **D004 — Compared user text is processed client-side and not persisted by default.** This is a core privacy property.
- **D005 — No backend, accounts, or authentication for the approved MVP.** Add them only through an explicit later decision.
- **D006 — GitHub Actions replaces local development verification in the mobile-only workflow.** Repository CI is the shared verification environment.
- **D007 — npm lockfile is generated by npm in GitHub Actions, never manually fabricated.** The bootstrap run must validate it before committing it.
- **D008 — Direct dependencies use exact versions.** Dependency upgrades are intentional repository changes.
- **D009 — MVP contains no ads, analytics SDKs, tracking pixels, or behavioral tracking.** Privacy takes precedence over premature monetization instrumentation.
- **D010 — Cloudflare deployment architecture is explicitly decided in Phase 0E.** Cloudflare Pages Direct Upload controlled by GitHub Actions is the approved model.
- **D011 — Browser QA uses Playwright in GitHub Actions.** Chromium exercises the built static application and responsive screenshots remain CI artifacts rather than committed assets.
- **D012 — Cloudflare Pages uses Direct Upload controlled by GitHub Actions.** Cloudflare Git integration is intentionally not used.
- **D013 — Same-repository PR previews are gated behind normal CI and Browser QA.** Fork-originated pull requests never receive Cloudflare deployment secrets.
- **D014 — Production deployment remains separate and non-automatic.** The original `compare.amosfot.in` plan was never activated and is superseded by the Phase 1E production-host decision in D040.
- **D015 — The comparison engine is framework-independent and exposes project-owned typed results.** UI code consumes the core API and does not depend directly on JsDiff types.
- **D016 — Line comparison can ignore case and leading/trailing whitespace while retaining both raw input lines.** Internal whitespace remains meaningful.
- **D017 — Adjacent remove/add replacement blocks pair positionally into changed rows.** Fuzzy or similarity-based line matching is intentionally deferred.
- **D018 — Core domain behavior is protected by Vitest unit tests before Browser QA and preview deployment.** A unit-test failure blocks downstream verification stages.
- **D019 — The main comparator is a focused Preact island inside a static Astro page.** Comparison logic remains framework-independent in `src/core/`.
- **D020 — Comparison is explicit and button-triggered.** Editing text or comparison options after a result marks that result stale until Compare is pressed again.
- **D021 — Compared text exists only in transient component state.** It is not persisted to browser storage, cookies, history, or URLs.
- **D022 — Result presentation is responsive without changing the core model.** Wider screens align Original and Changed side-by-side; narrow screens stack the paired sides within each comparison row.
- **D023 — The product uses a dark-default dual-theme visual system.** Dark is the first-visit default regardless of OS color preference; Light is an explicit user choice.
- **D024 — Only the non-sensitive theme preference may persist in localStorage.** The `private-text-compare-theme` key may contain only `dark` or `light`; compared text, results, comparison options, and comparison history remain transient and clear on reload.
- **D025 — The product visual identity follows a restrained precision/developer-editor direction.** Neutral chrome, minimal elevation, compact gutters, and semantic diff colors focus attention on actual text changes rather than decorative application surfaces.
- **D026 — Theme state is applied before normal page paint.** The static document defaults to dark and a small head bootstrap restores only a valid saved theme before the page renders, preventing an avoidable light flash.
- **D027 — Product typography uses self-hosted Geist Sans and Geist Mono from a pinned upstream release.** The two variable WOFF2 assets come from official `vercel/geist-font` tag `v1.7.1`, are served same-origin, and create no third-party runtime font request.
- **D028 — The ambient page background uses a static CSS technical-canvas system instead of a uniform graph-paper repeat.** A minor grid, a major grid at four minor cells, aligned major-intersection nodes, restrained illumination, and spatial fading create the approved structure.
- **D029 — Decorative canvas treatment remains non-interactive, theme-aware, and subordinate to editor surfaces.** It uses pseudo-elements and CSS only, with no runtime JavaScript renderer, image/SVG background asset, canvas element, or animation.
- **D030 — Export serialization consumes project-owned `ComparisonResult`.** It does not rerun JsDiff or implement a second comparison algorithm, so exported output reflects the active comparison semantics, including ignore options.
- **D031 — Copy and file export are explicit local browser actions.** Export payloads are not persisted, transmitted, logged, or included in URLs; clipboard access is write-only and user initiated.
- **D032 — Stale results are not exportable.** Editing inputs or comparison options after Compare disables Copy/Export until the comparison is refreshed.
- **D033 — Phase 1C export formats are deterministic.** Unified-diff and plain-text report outputs use fixed non-sensitive filenames and contain no timestamps or inferred document names.
- **D034 — Launch explanatory content stays static and below the primary comparator.** Phase 1D guidance, privacy copy, common uses, and FAQ use Astro-rendered semantic HTML and add no hydrated island.
- **D035 — SUPERSEDED by D040. The Phase 1D planned canonical production host was `https://compare.amosfot.in/`.** It was a build-time plan only, was never activated as a Pages custom domain or DNS target, and has no live legacy URL to migrate or redirect.
- **D036 — Launch metadata is static and deliberately narrow.** The document head contains canonical, Open Graph, Twitter summary metadata, and one `WebSite` JSON-LD object for site identity only; no FAQPage, rating/review, offers, SearchAction, or invented organization/person schema is added.
- **D037 — Crawling assets describe the eventual production site while previews remain noindex at the deployment layer.** `robots.txt` allows crawling and points to the production sitemap; `sitemap.xml` lists only the canonical homepage; Cloudflare PR previews continue to rely on `X-Robots-Tag: noindex` rather than HTML noindex metadata.
- **D038 — Launch identity assets remain local and static.** The favicon is an original standalone SVG served from `/favicon.svg`, with no external font, raster, or runtime dependency.
- **D039 — Phase 1D adds no runtime dependency, data flow, or hydration path.** Existing comparator/theme islands remain the only hydrated interaction; launch content and SEO assets introduce no persistence, analytics, tracking, backend, external runtime request, or compared-text handling.
- **D040 — The canonical production host is `https://textcompare.amosfot.in/`.** Astro `site` is the build-time source for canonical/social site identity; the earlier D035 host was planned only and never activated.
- **D041 — SUPERSEDED by D044. Production releases were initially exact-current-main `workflow_dispatch` only.** Phase 1E-A required a full `target_sha`, `refs/heads/main`, equality with `github.sha`, and a fresh `origin/main` check; PR and normal main pushes remained non-production. Phase 1E-A2 retains that dispatch path as a fallback while adding a connector-operable release-ref trigger.
- **D042 — Pages custom-domain association is controlled through the Pages API without direct DNS mutation.** After exact production provenance is proven, `textcompare.amosfot.in` is associated idempotently using the existing Pages-scoped credentials; an unexpected `compare.amosfot.in` association or non-active validation state fails safely for review rather than mutating DNS or broadening permissions.
- **D043 — Preview and production indexability are intentionally different.** PR previews must continue returning `X-Robots-Tag: noindex`; the production custom domain must be HTTPS 200, carry the approved canonical/structured-data/crawling assets, contain no HTML noindex, and return no `X-Robots-Tag: noindex` before a release is considered verified.
- **D044 — Production release has two explicit exact-current-main entry points.** `workflow_dispatch` remains the fallback, while an approved GitHub `create` event for a release branch provides a connector-operable trigger. Both routes resolve one exact target SHA, require actor `AltamashM7`, and fail unless a fresh fetch proves that target is still current `origin/main` before verification and again immediately before deployment.
- **D045 — Connector release refs are immutable audit markers with retry suffixes.** The only accepted create-trigger format is `release/production/<40-lowercase-hex-SHA>-r<N>` where `N` is a positive integer beginning at 1; the embedded SHA must equal the created branch tip/event SHA. Retry branches (`-r2`, `-r3`, …) avoid any dependency on branch deletion while retaining prior attempts for audit.
- **D046 — Production release attempts publish a connector-readable commit-status receipt.** Context `production/private-text-compare` is written against the resolved target SHA with the exact Actions run URL, using only job-local `statuses: write` plus `contents: read`; pending is published after Verify succeeds, and an always-run finalizer publishes success only when the entire release chain succeeds, otherwise failure. Global workflow permissions remain `contents: read` and no `contents: write` is granted.
- **D047 — Production DNS remains manually managed to preserve least privilege.** `textcompare.amosfot.in` uses a proxied CNAME from `textcompare` to `private-text-compare.pages.dev`. The GitHub/Cloudflare deployment token remains Pages-scoped and DNS Write was deliberately not added because production DNS setup is rare and does not justify permanent broader secret capability.
- **D048 — Repository `robots.txt` is authoritative for the production crawler policy.** Cloudflare Managed robots.txt is disabled for this zone/deployment arrangement so `public/robots.txt` is served as the deliberate repository-owned policy. Production release verification requires the live crawler directives to match that approved repository policy.
